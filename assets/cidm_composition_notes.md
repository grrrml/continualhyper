## 2. The composition protocol (ITP + RTP + box)

Sec. 4.3, "Conditional Generation", verbatim `[PAPER]`:

> Besides the initial text prompt **p̂** defined in Sec. 4.2, users can provide U pairs of region conditions {**p̂**_u, **ŝ**_u}_{u=1}^{U}, where **ŝ**_u is the bounding box to synthesize concepts related to the u-th region text prompt **p̂**_u.

and, on how the box enters the attention:

> **m̂**_u^l ∈ ℝ^{h^l×w^l} is the binary region mask in the l-th layer, where the values inside the bounding box **ŝ**_u are set to 1. Ω(·) can retain only the features inside **ŝ**_u [...] Then, the values of **f**^l inside the bounding boxes {**ŝ**_u}_{u=1}^{U} are respectively replaced with the corresponding region features {**f**_u^l}_{u=1}^{U} to obtain a new feature map **f̂**^l. We apply the layer-wise regional cross-attention to all layers of ε_{θ*'}(·) for conditional generation.

Supplementary A.4, verbatim `[PAPER]`:

> Particularly, given an initial text prompt (ITP) and some region text prompts (RTP) with users-provided bounding boxes, all comparison methods exhibit significant concept neglect and they are difficult to perform multi-concept customization.

Also `[PAPER]`: region noise estimations are aggregated as `E*^t = α·E^t + Σ_u (1−α)·E_u^t ⊙ m̂_u^L` with **α = 0.1** and classifier-free guidance **s = 7.5** (Eq. 4–5, Sec. 4.3 / Sec. 5.1).
Fairness note `[PAPER]`: "we incorporate the regionally controllable sampling module proposed in [Mix-of-Show] into existing comparison methods" — i.e. the baselines in Figs 3/12 get Mix-of-Show regional sampling, CIDM gets its own CCS.

**That is the entire specification of how regions are given.** The paper never states box coordinates, a canvas aspect ratio, or how a user is expected to draw them. The only depiction of the boxes is the "Region Boxes" / "Input" panel of Figs 3, 6, 12.

### The three internal inconsistencies — do not propagate them

1. **Fig 3 scene 3.2 (bedroom).** The RTP reads `V9 dog | V3 cat | V7 cat` but the region-box labels in the very same panel read V7 **dog** and V9 **cat**. Fig 12's version of the same scene reads `V7 dog | V3 cat | V9 cat`, which agrees with the boxes and with the dataset definition. `[FIGURE]` `[INFERENCE]` the Fig 3 RTP string is wrong.
2. **Fig 3 scene 3.5 (moon).** Both the RTP and the box label say "V9 dog", but the dataset section says "V1 dog, V2 duck toy, V3 cat, V4 backpack, V5 teddy bear, V7 dog and V9 cat" `[PAPER]` — V9 is a cat. `[INFERENCE]` this is a mislabelled V7 dog. If we reproduce this scene we must pick one reading and say which.
3. **The RTP order is not the left-to-right box order** in scenes 3.2, 3.4, 3.5 and 12.1. Pairing is by colour only. Anyone re-typing these prompts from the figure will get the assignment wrong unless they use the table above.

## 5. Known versus must-be-chosen-by-us

### Stated by the authors

* Backbone for the composition figures: **SDXL** `[PAPER]` (Figs 3, 12 captions). Fig 6 names no backbone; `[INFERENCE]` it is SDXL too, since its embedded samples are 1024 px.
* ITP and RTP strings for all 11 rows of Figs 3 and 12, verbatim. `[FIGURE]`
* Which concept goes in which box, and the box geometry as drawn. `[FIGURE]` / `[MEASURED]`
* Classifier-free guidance scale **s = 7.5** `[PAPER]`; region/global blend **α = 0.1** `[PAPER]`.
* Training: LoRA rank r = 4, 800 steps, lr 1e-3 (textual embeddings) / 1e-4 (UNet), two RTX 4090s, **random seed 0** "for all comparison experiments" `[PAPER]`.
* Baselines in Figs 3/12 use Mix-of-Show regional sampling. `[PAPER]`
* The evaluation prompt set (Fig 9: 20 prompts each for pets / objects / styles) is **single-concept only** — every entry contains one `[V*]`. It contains none of the composition prompts, which is consistent with there being no composition prompt file in `datasets/`. `[FIGURE]`

### Not stated anywhere — we choose, and must declare in our caption

1. **Output resolution for the composition figures.** The word "resolution" never appears in the paper, and no height/width is given anywhere. `[PAPER]` The bitmaps embedded in the e-print figures are **1024 x 1024** for every SDXL panel (Figs 3, 11, 12) and **512 x 512** for every SD-1.5 panel (Fig 2), i.e. native for each backbone. `[MEASURED]` `[INFERENCE]` composition was rendered at 1024 x 1024 — strong, but still our inference; the figures could in principle have been resampled before embedding.
2. **Sampler and step count for the composition figures.** Not stated. `[PAPER]` The released `inference.py` — which is the *single-concept* SD-1.5 driver — uses `DPMSolverMultistepScheduler`, `num_inference_steps=50`, `guidance_scale=7.5`, `torch.Generator('cuda').manual_seed(2024)`. `[CODE]` Carrying those over to the SDXL composition figures is an assumption.
3. **Seed.** Paper says 0 `[PAPER]`; released code hard-codes 2024 `[CODE]`. Not resolvable from outside; pick one and state it.
4. **Negative prompt.** The paper says the quantitative sampling used "a unify negative prompt" but never prints it `[PAPER]`. The repo's is `longbody, lowres, bad anatomy, bad hands, extra digit, fewer digits, cropped, worst quality, low quality` `[CODE]`. Whether the composition figures used any negative prompt is unknown.
5. **Whether the drawn rectangles are the literal ŝ_u.** The "Region Boxes" panel is presented as an illustration; the paper never says it is to scale. `[INFERENCE]` it is — the panels are square, matching the 1:1 output aspect, and the rectangles are tight and non-overlapping in a way that reads as the actual condition. Our measured coordinates are therefore the best available reconstruction, not a published specification.
6. **Samples per scene, and any selection among them.** Nothing said. There is **no table and no user study** for composition — the comparison is qualitative only, which is what makes a like-for-like visual reproduction the right response.
7. **Which SDXL checkpoint** (base only vs. base+refiner, exact revision). Not stated. `[PAPER]`

### Reproducibility ceiling of the release

The released repo has `lib/models/attention.py::RegionT2I_AttnProcessor` but no driver that constructs it, and `lib/pipelines/` contains only `pipeline_edlora.py`, an SD-1.5 EDLoRA pipeline. A case-insensitive `grep` for "xl" over `lib/` and `inference.py` returns **nothing** `[CODE]` — there is no SDXL pipeline in the release at all. So the SDXL composition figures cannot be regenerated from the released code even in principle, independently of the missing prompts. That deserves one sentence in the paper if we claim we could not re-run their method.

### Suggested caption boilerplate for our figure

> CIDM results are reproduced from Fig. 12 of Dong et al. [cite]; the region boxes and the ITP/RTP prompts are theirs. Our results use the same prompts and the same box layout, rendered with SDXL at 1024x1024, DPM-Solver++ with 50 steps, CFG 7.5, seed &lt;s&gt;. The paper does not state the resolution, sampler, step count or seed used for its composition figures (its text reports seed 0, while its released inference code hard-codes 2024), so these are our choices and the comparison is not seed-matched.
